# Kafka 与异步处理

## 药房预约订单

预约 API 先以 Redis Lua 完成限流、活动库存预留和请求幂等校验。通过后写入预约/Outbox 记录，由 relay 投递预约事件；消费者幂等创建订单、按 FEFO 分配有效批次，并在 MySQL 事务中更新批次数量和库存流水。可重试失败保留待处理状态，超过处理能力的消息进入死信记录；超时或取消路径会释放活动预留。

关键状态由 MySQL 保存，API 重试以 idempotency key 识别同一请求。Redis 预留不是订单完成的证明，订单最终状态以 MySQL 查询为准。

## 原有聊天消息

原聊天功能使用 `push-topic` 实时推送、`store-topic` 异步落库，消费者使用不同消费组。Kafka 事务覆盖两个 Kafka Topic 的写入；Kafka 与 MySQL 之间不构成跨系统事务。

## 运行与验证边界

当前测试 Compose 使用单 Broker，没有生产级副本容灾。已验证单请求预约、幂等重试、Kafka 消费创建订单、门店核销和批次账本结果；尚未完成 Broker 中断、重复/乱序投递、积压恢复、消费者再平衡和高并发压测。
